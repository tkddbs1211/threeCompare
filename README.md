## 2. 성능 비교 및 결과 분석

### 1) 트리 높이(Height) 차이 분석
* **BST (높이: 13)**: 데이터가 무작위로 삽입되더라도 편향(Skewed) 현상이 일부 발생하여 트리의 한쪽 가지가 길게 형성될 수 있습니다. 이로 인해 트리의 높이가 상대적으로 높게 측정됩니다.
* **AVL 트리 (높이: 8)**: 노드가 삽입될 때마다 균형 인자(Balance Factor)를 확인하고 **회전(Rotation) 연산**을 수행하여 자가 균형을 유지합니다. 이에 따라 94개의 데이터를 저장함에 있어 이론적 최적 높이에 가까운 8을 유지했습니다.

### 2) 구축 비용 (Construction Comparisons) 분석
* **배열 (4,602회)**: 데이터를 추가할 때마다 중복 체크를 위해 기존 배열 요소 전체를 선형 탐색해야 하므로 $O(N^2)$ 수준의 매우 높은 비교 횟수가 발생합니다.
* **BST (609회) vs AVL (526회)**: AVL 트리는 초기 구축 과정에서 트리 높이를 낮게 유지하므로 노드가 누적될수록 새로운 노드가 들어갈 위치를 찾는 비교 횟수가 BST보다 오히려 적게 발생함을 확인할 수 있습니다.

### 3) 탐색 성능 (Search Comparisons) 분석
* **순차 탐색 (평균 92.40회)**: 배열을 처음부터 끝까지 검색하므로 데이터가 존재하지 않을 때(`Not Found`) 무조건 전체 데이터 크기(94회)만큼의 비교가 발생하여 효율성이 가장 떨어집니다 ($O(N)$).
* **BST 탐색 (평균 8.12회)**: $O(\log N)$에 가까운 빠른 성능을 보여주지만, 트리의 높이가 높아서 특정 키(예: Search Key 567) 탐색 시 최대 13회의 비교가 필요했습니다.
* **AVL 트리 탐색 (평균 6.72회)**: 엄격하게 균형을 유지한 덕분에 탐색 시 경로가 짧아져 평균 비교 횟수가 세 자료구조 중 가장 적었으며, 어떤 키를 찾더라도 안정적으로 가장 뛰어난 탐색 성능을 보였습니다 ($O(\log N)$ 보장).<img width="650" height="884" alt="트리비교4" src="https://github.com/user-attachments/assets/e35ec41c-1cf1-454e-9a6e-1227c9e6f6fd" />
